## 1. 产品定位

### 1.1 目标设备画像

目标真机：**MiDuoKanReaderPro** 墨水屏阅读器（Android 8.1 / SDK27 / armeabi-v7a，已实测）。**其余参数为设计基线，随实测持续校准**：

| 维度 | 基线假设 | 设计对策 |
|---|---|---|
| 屏幕 | 6"–7.8" 墨水屏，300ppi，16 级灰阶 | 纯黑白灰设计；灰阶 5 级封顶 |
| 芯片 | **实测：armeabi-v7a（32 位）** | 无 native 依赖，纯 Kotlin 运行（APK 与 ABI 无关） |
| 内存 | 1–2GB RAM | 控制 APK ≤ 12MB；列表图片零常驻 |
| 系统 | **实测：Android 8.1（SDK27）** | `minSdk 23` / `targetSdk 34` / `compileSdk 36`（兼容已验证） |
| 安装通道 | ROM 阉割了"安装未知应用"系统页（第三方安装器唤起失败） | 走系统文件管理器 / adb 安装，不依赖第三方安装器跳转 |
| 刷新 | 局部刷新约 300ms，全刷 1–3s（含黑闪） | **零动画**；变化按块、低频跳变（§3.6） |
| 输入 | 触屏（响应迟钝），部分机型带物理键盘 | 触区 ≥ 48dp；支持物理键盘快捷键 |
| 网络 | Wi-Fi，可能不稳定 | 离线提示；120s 长超时；失败可重试 |
| 存储 | 8–32GB，可能紧张 | 数据库 + 文本为主；导出压缩；缓存可清 |

### 1.2 三条产品守则

1. **安静优先**——一切设计服务于"读一段对话"，不是"玩一个 App"。凡不能提升阅读性的元素，删除。
2. **重活交给云端**——设备只负责排版、输入、存储；推理、联网搜索、图片理解全部由 DeepSeek API 完成。
3. **离线不残缺**——历史、搜索、导出、设置完全离线可用；联网只影响"新消息"这一件事。

### 1.3 范围边界

| 做（P0 起） | 不做（并说明理由） |
|---|---|
| 多轮对话、思维链、联网搜索、图片输入 | ❌ 语音输入 / TTS 朗读（7 年设备上效果差、耗资源） |
| 会话管理（新建/重命名/删除/置顶/搜索/总结） | ❌ 多账号 / 云同步（无账号体系，数据即设备） |
| 导入导出、备份恢复、余额与用量 | ❌ 插件 / 主题商店 / 社区（墨水屏是私人物品） |
| 字号/行距/主题（含反色）显示设置 | ❌ 富文本编辑、代码高亮级编辑器 |
| 墨水屏专项：全刷工具、跳转按钮、物理键盘 | ❌ 动画、手势依赖、滑动删除 |

### 1.4 三条用户故事（验收时的感性标准）

- 「在读书间隙，我把问题发给它，等答完，慢慢读——像翻一页书。」
- 「我把一段代码贴进去，出门前发好，回来时答案已经端正如印刷。」
- 「我从不管理数据，但所有对话都在，随时导出。」

### 2.2 核心流程状态机

**① 发送消息（主流程）**

```text
用户输入 → 保存 user 消息（DB）
   ↓
构建请求负载（历史消息 + thinking/effort + 联网开关）
   ↓ 联网开 → POST /responses + tools[web_search]，拼接历史 reasoning_content
   ↓ 联网关 → POST /chat/completions
   ↓
[等待] 显示"正在思考…（已 N 秒）"（5s 离散跳变，可点"停止"）
   ↓                              ↘ 取消 → 标记"已中止"，保留半截
成功 → 保存 assistant（content + reasoning_content + usage）
   ↓
界面块级刷新（新消息一次性绘出）
   ↓
失败分类：429 → 自动退避重试（≤3 次，界面提示第几次）
          401/402/400/422 → 立即失败 + 对应文案（§3.5）
          5xx → 重试 2 次后失败
          网络层 → "连接失败" + 重试按钮
```

**② 对话总结**

```text
列表项菜单 [总结] → 校验非空会话 → 组装全量对话文本
→ /chat/completions（thinking: disabled）
→ 返回摘要 → 追加为 assistant 消息（标注 "· 摘要"）→ 列表刷新
```

**③ 图片输入**

```text
[+] 选择图片（SAF / 相册）→ 本地预校验（JPEG/PNG/GIF/WebP，≤64MiB）
→ POST /files（multipart，purpose=user_data）→ 得 file_id
→ 消息附带 attachments=[file_id] → 该次请求自动切换 vision 模型
→ 消息列表中显示为 "[图片] 文件名" 占位行（点击可查看）
```

**④ 导出 / 导入**

```text
导出：选择会话(或全部) → 组装 JSON → SAF 创建文档 → 写入 → 提示完成
导入：SAF 选择文件 → 解析校验 version → 事务写入 DB → 提示 N 个会话已导入
```

## 3. 界面设计系统 ——「纸面语言」

> 本章是"界面美观"的全部依据。开发时**禁止**任何不在本系统中的颜色、间距、图标、动效。

### 3.1 纸面六则（设计原则）

1. **版面即内容**——没有装饰层。不使用卡片阴影、渐变、色块堆叠；界面的美来自留白、对齐与排版本身。
2. **静止之美**——动画是负资产。状态变化一律**瞬时完成**：弹窗瞬间出现、列表瞬间更新、按钮点击后直接看结果。
3. **线条语法**——版面由 1dp 直线组织：分割线、边框、引用线、下划线。直角（radius=0），无圆角、无阴影。
4. **灰阶克制**——只用 5 级：纸白、浅灰、中灰、深灰、墨黑。**任何色相（红绿蓝黄）禁止出现**，包括错误提示（用符号 + 加粗 + 框线表达）。
5. **离散刷新**——可视变化按"块"发生、以低频跳变；拒绝一切连续动画：进度条、光标闪烁最弱化、点状 loading 等传统动效**全部换成静态表达**。
6. **宽容触控**——触区不小于 48dp，一切操作"点得到"：无长按菜单、无滑动删除、无手势返回依赖（物理返回键正常）。

### 3.2 设计令牌（Design Tokens）

**色彩（16 级灰阶设备上，5 级封顶）**

| Token | 值 | 用途 |
|---|---|---|
| `Paper` | `#FFFFFF` | 页面底色 |
| `Mist` | `#F2F2F2` | 极淡填充（选中行、代码块底）——大面积慎用 |
| `Line` | `#B8B8B8` | 1dp 分割线、次级边框 |
| `InkMid` | `#6E6E6E` | 辅助文字（时间、元信息、占位符） |
| `InkDeep` | `#2B2B2B` | 次级正文、用户消息正文 |
| `Ink` | `#000000` | 主文字、标题、图标、重点线 |
| `Inverse` | 黑底白字 | 强调态：主按钮、选中项、重点标签 |

> 反色是墨水屏上唯一的"强调色"。重要元素用**反色块**、**加粗**或**线框**表达，绝不用彩色。

**字号与行高**（基准：正文 19sp；全局缩放 0.85 / 0.9 / 1.0 三档，默认 0.9）

| Token | 大小/行高 | 字重 | 用途 |
|---|---|---|---|
| `T-Display` | 22 / 32 | 600 | 空态标语、余额数字、大标题 |
| `T-Title` | 19 / 28 | 600 | 对话标题、区块标题、对话框标题 |
| `T-Body` | 19 / 32 | 400 | 消息正文、说明文字 |
| `T-Alt` | 15 / 26 | 400 | 列表副标题、次级说明、输入提示 |
| `T-Caption` | 13 / 22 | 400 | 时间、模型名、用量、按钮小字 |
| `T-Mono` | 15 / 24 | 400 | 代码（等宽）、编号 |

数字统一使用**等宽数字特性**（`fontFeature("tnum")`），保证时间与用量对齐。

**间距（8dp 网格）**

| Token | 值 | 场景 |
|---|---|---|
| `Pad-Page` | 20dp | 页面左右边距（内容区最大宽度 600dp 居中） |
| `Pad-Block` | 16dp | 区块之间 |
| `Pad-Line` | 12dp | 列表行内上下 |
| `Pad-Tight` | 8dp | 行内元素之间 |
| `Touch` | ≥48dp | 一切可点区域 |

**线与角**

- 分割线：1dp，`Line` 色；强调线：1.5dp 黑。
- 圆角：**0dp**（全局直角，含按钮、对话框、输入框）。
- 阴影：**禁止**（墨水屏上的阴影=一团脏灰）。
- 焦点/选中：2dp 黑下划线 或 反色块。

**图标**

- 24dp 网格，线宽 1.5dp，**全部 outlined 风格**，颜色仅 `Ink`。
- 使用 `material-icons-extended`，禁用 filled 变体（选中态用反色底解决）。

**符号代替颜色（语义表达）**

| 语义 | 表达 |
|---|---|
| 成功/完成 | `✓` + 常规黑字 |
| 失败/错误 | `！` + 加粗 + 1.5dp 黑框内联条 |
| 警告 | `△` + 常规黑字 |
| 进行中 | `▸` + 文字（无转圈动画） |

### 3.3 组件库（13 件套）

每件给定尺寸与状态；实现见 §4.7 的 Compose 配置。

**① 顶栏 TopBar**（高 56dp）
左：返回/目录图标按钮（48dp 触区）｜中：标题（`T-Title`，超长省略）｜右：最多 2 个图标按钮。底部 1dp 分割线。

**② 底部输入区 Composer**
上沿 1dp 分割线；内部一行：
`[联网 ○] [思考·低 ▾]`（分段开关，见 ⑫）＋ 输入框 ＋ 发送按钮。
输入框：1.5dp 黑框、内边距 12dp、直角、最大 6 行内滚；占位符"输入消息…"（`InkMid`）。
发送按钮：48dp 反色方块，图标 `send`；生成中变为"停止"（黑框白底）。

**③ 主按钮（反色）**
黑底白字，高 48dp，水平内边距 20dp，`T-Body` 加粗；按压无反馈动画，点击后立即执行。

**④ 次按钮（线框）**
白底黑字，1.5dp 黑框，其余同③。

**⑤ 文字按钮**
黑字（或 `InkDeep`），`T-Alt`，触区 48dp；链接样式加 1dp 下划线。

**⑥ 图标按钮**
48dp 触区内 24dp 图标；禁用态 `Line` 色。

**⑦ 列表项**
高 ≥56dp；左图标（可选）｜主标题 `T-Body`｜副标题 `T-Caption`（`InkMid`）｜右侧动作（图标按钮或文字按钮）；底部分割线缩进或全宽。
选中态：整行反色。

**⑧ 消息块**（核心，去气泡化书页排版）
- 用户消息：左侧 2dp 黑引用线 + 左缩进 12dp；正文 `InkDeep`。

- 空状态：垂直居中，`T-Display` 标语 + `T-Alt` 说明 + 可选主按钮。

### 3.6 墨水屏渲染策略（工程化落地）

**A. 离散刷新设计法——"连续量 → 块级量"映射表**

| 传统做法（禁用） | 本项目做法 |
|---|---|
| 旋转 Loading | 静态文字 `正在思考…`（每 5s 更新一次秒数） |
| 平滑进度条 | 10 段式字符刻度 `━━━━━─────`（仅阶段变化时重绘） |
| 光标闪烁 | 输入态接受最小局部刷新；非输入态不显示光标 |
| 淡入淡出 / 位移转场 | 瞬时切换（无过渡） |
| 涟漪 / 按压渐变 | 无按压动画；点击后直接看结果 |
| 自动消失 Toast | 内联提示条，停留页面由用户关闭 |

**B. 残影与全刷**

- 页面级切换（对话 ↔ 列表 ↔ 设置）：整页重绘，天然接近全刷，残影少。
- 长滚动 / 大量跳转后出现残影 → 用户执行"清屏重绘"（设置页或顶栏入口）；部分阅读器系统自带快刷/全刷切换，交给系统。
- **不做**自动全刷（黑闪被用户视为干扰）；把控制权交给用户。

**C. 滚动与跳转**

- 滚动：关闭惯性 fling（松手即停），减少连续刷新；关闭滚动条。
- 跳转：先粗定位（索引 × 估算高度），后 `ensureVisible` 精定位（无动画，见 §4.7）。
- 列表：`LazyColumn` 固定 key；不预取视口外内容。

**D. 输入体验**

- 物理键盘：`Enter` 发送、`Shift+Enter` 换行、`Esc` 关闭弹窗、`Tab` 在按钮间移动。
- 软键盘：输入区随键盘上移；大触区；长文建议用"写作台"。
- 输入过程不做实时字数统计等频繁刷新元素。

**E. Compose 侧硬性配置清单**（实现见 §4.7）

- 全局 `indication = null`（无涟漪）+ 禁止 `Animated*` 组件。
- `NavHost` 全部过渡设为 `EnterTransition.None` / `ExitTransition.None`。
- 所有 `LazyColumn` 关闭 fling、稳定 key。
- 主题不启用 Material3 动态色/海拔阴影；自定义 `Ink` 令牌全覆盖。
- 不使用 `HorizontalPager`、`AnimatedVisibility`、`CircularProgressIndicator`。

## 4. 技术架构

### 4.1 技术选型决策

| 方案 | 优势 | 在本项目的风险 | 结论 |
|---|---|---|---|
| **Kotlin + Jetpack Compose**（选定） | 与 novel-agent 同栈；构建链路已在**同一台设备、同一工具链**上完成 12.6MB release 出包与装机验证；Keystore/SSE/重试等模块可直接移植；无 native 依赖 | 需真机确认 Compose 在老设备上的首帧速度 | ✅ 采用 |
| Flutter | 自绘排版能力强 | 设备端 proot 构建链路**未验证**（SDK/engine 下载近 1GB、arm64 host 工具链未跑通）；引擎层内存开销；与既有 Kotlin 资产零复用 | ❌ 否决 |
| Kotlin + XML View | 老设备最轻 | UI 代码量约翻倍；无既有资产 | 备选（降级预案） |

**结论与理由（三条）**：

1. **复用性**——novel-agent 已验证整套通路：网络（SSE 流式、退避重试）、安全（Keystore AES-GCM）、数据（Room + kapt 模式）、构建（Gradle/AGP/aapt2 绕过）、发布（签名、安装、验证）。本项目**直接继承**，预计节省约 1/3 开发量。
2. **构建风险**——《构建心得.md》的核心教训："设备上构建，80% 时间在环境"。Flutter 路线等于把环境学费再交一遍，且结果未知。本项目不承担该风险。
3. **体积与内存**——纯 Kotlin、无 native so，APK 约 12MB 级（novel-agent 实测 12.6MB）；无引擎层，冷启动更短，缓存在 1–2GB RAM 设备上更宽裕。

> **降级预案**：若真机实测 Compose 性能不达标，保持设计系统、数据层、网络层不变，UI 改用 XML View 重写——架构分层已为此预留隔离（§4.2）。

### 4.4 数据层

**Room 表结构（完整 DDL，字段名显式 snake_case）**

> 【心得·代码层 Room-1】Kotlin 属性 camelCase 与 SQL snake_case 必须显式对齐（`@ColumnInfo`），否则运行时 `no such column`。

```sql
CREATE TABLE conversations (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    title       TEXT    NOT NULL DEFAULT '新对话',
    pinned      INTEGER NOT NULL DEFAULT 0,          -- 0/1
    archived    INTEGER NOT NULL DEFAULT 0,          -- 0/1（P1）
    created_at  INTEGER NOT NULL,                    -- epoch millis
    updated_at  INTEGER NOT NULL
);

CREATE TABLE messages (
    id                 INTEGER PRIMARY KEY AUTOINCREMENT,
    conversation_id    INTEGER NOT NULL,
    role               TEXT    NOT NULL,             -- user | assistant
    content            TEXT    NOT NULL DEFAULT '',
    reasoning_content  TEXT,                         -- 思维链，可空
    attachments        TEXT,                         -- file_id 的 JSON 数组，可空
    status             TEXT    NOT NULL DEFAULT 'done',  -- done | canceled | failed
    error              TEXT,                         -- 失败原因摘要（可空）
    prompt_tokens      INTEGER,                      -- 可空（响应回传时写入）
    completion_tokens  INTEGER,                      -- 可空
    think_ms           INTEGER,                      -- 思考时长 ms，可空（仅流式可测：首正文抵达 − 请求发出）
    created_at         INTEGER NOT NULL,
    FOREIGN KEY (conversation_id) REFERENCES conversations(id) ON DELETE CASCADE
);
CREATE INDEX idx_msg_conv_time ON messages (conversation_id, created_at);

CREATE TABLE usage_logs (                            -- 用量流水（§3.4 余额页数据源）
    id               INTEGER PRIMARY KEY AUTOINCREMENT,
    conversation_id  INTEGER,
    model            TEXT,
    input_tokens     INTEGER,
    output_tokens    INTEGER,
    created_at       INTEGER NOT NULL
);

CREATE TABLE models_cache (                          -- 模型列表缓存
    id          TEXT PRIMARY KEY,                    -- 模型 ID
    fetched_at  INTEGER NOT NULL
);
```

**开发期与迁移策略**：开发阶段 `fallbackToDestructiveMigration()` 省事【心得·代码层 Room-3】；**首次发布起**换用正式 `Migration`，版本号每次结构变更 +1。

### 4.5 网络层

**API 调用矩阵**

| 端点 | 方法 | 用途 | 触发时机 |
|---|---|---|---|
| `/chat/completions` | POST | 普通对话、对话总结 | 发送消息 / 总结 |
| `/responses` | POST | 联网搜索对话（原生 `web_search`） | 联网开关 = 开 |
| `/files` | POST | 图片上传（multipart，`purpose=user_data`） | 选择图片 |

| `/models` | GET | 模型列表 | 启动时刷新并缓存 |

**请求装配规则**

```text
普通对话（联网关）：
    POST /chat/completions
    body = { model, messages: 全量历史, stream: false,
             thinking: {"type": "enabled" | "disabled"},
             reasoning_effort: "low" | "high" | "max" }      // 仅思考开启时携带

联网搜索（联网开）：
    POST /responses
    body = { model, messages/*含历史 reasoning_content*/, tools: [{"type":"web_search"}] }

对话总结：
    POST /chat/completions
    body = { model, messages: [拼接的全量对话文本], thinking: {"type":"disabled"} }
```

**思维链回传规则（易错点，单独强调）**

| 场景 | 历史轮次 `reasoning_content` | 实现 |
|---|---|---|
| 请求**不带** `tools` | 无需回传（传了也被忽略） | 装配时省略该字段 |
| 请求**带** `tools`（联网搜索） | **必须回传全部历史轮次** | 装配时拼回 `reasoning_content` |

```kotlin
fun buildMessages(history: List<Message>, useTools: Boolean) = history
    .filter { it.status != MessageStatus.FAILED }
    .map { m ->
        if (m.role == "assistant" && useTools)
            Msg(m.role, m.content, reasoning = m.reasoningContent ?: "")
        else Msg(m.role, m.content)                 // reasoning 省略
    }
```

**SSE 流式解析规范**（`stream=true` 时启用，语义来自【心得·代码层 11–12】）

- 按行读取；仅处理 `data: ` 前缀行；`[DONE]` 收尾。
- delta 中区分 `content`（正文）与 `reasoning_content`（思维链），各自累积。
- JSON 容错清洗：剥离 ```json 围栏、尾逗号容忍（复用 `JsonCleaner`）。
- **墨水屏适配**：不在每个 delta 刷新 UI；按"段"批量提交（每累积 ≥ 200 字符或遇到段落边界时提交一次），结束时一次收尾。

**超时与重试**

| 项 | 值 |
|---|---|
| 连接超时 | 10s |
| 读取超时 | 120s（流式场景禁用读取超时） |
| 429 | 指数退避：1s → 2s → 4s → 8s（±50% 抖动），最多 3 次；尊重 `Retry-After` |
| 5xx | 最多重试 2 次 |
| 并发保护 | 同会话串行（单飞行请求）；客户端请求速率 ≤ 2 次/秒 |

**错误码映射（→ 文案与动作，与 §3.5 对齐）**

| 码 | 含义 | 界面表现 |
|---|---|---|
| 400 | 格式错误 | 「！请求格式错误」+ 重试 |
| 401 | 认证失败 | 「！API Key 无效或已过期」+ 去设置 |
| 402 | 余额不足 | 「！余额不足，请充值」+ 去查询 |
| 422 | 参数错误 | 「！参数错误」+ 重试 |
| 429 | 限流 | 自动重试 + 状态行提示第几次 |
| 500 | 服务器故障 | 「！服务内部错误」+ 重试 |
| 503 | 服务器繁忙 | 「！服务暂时不可用」+ 重试 |
| 无网络 | IOException | 「！连接失败：无法访问 api.deepseek.com」 |

**模型列表与缓存**：`GET /models` 对 ID 做模糊匹配（含 `deepseek` 即纳入，避免 ID 变更导致下拉为空）；结果写入 `models_cache`，启动时静默刷新一次。已知模型：`deepseek-v4-flash`、`deepseek-v4-pro`、`deepseek-v4-flash-vision-exp`。

## 附录 A · DeepSeek API 速查（v2.0 口径）

> 以下为本项目实现所依据的 API 事实（源自官方文档检索与实际使用验证）。此后官方若有变更，以 [api-docs.deepseek.com](https://api-docs.deepseek.com) 为准。

**A.1 端点总览**

| 端点 | 方法 | 用途 |
|---|---|---|
| `/chat/completions` | POST | 普通对话（无状态） |
| `/responses` | POST | 联网搜索（原生 `web_search`） |
| `/files` | POST / GET | 上传文件（目前仅图片）/ 列出 |
| `/files/{file_id}` | GET / DELETE | 查询 / 删除已上传文件 |
| `/user/balance` | GET | 账户余额 |
| `/models` | GET | 模型列表 |

Base URL：`https://api.deepseek.com`

**A.2 思考模式**

| 控制维度 | OpenAI 格式 | Anthropic 格式 | Responses 格式 |
|---|---|---|---|
| 思考开关 | `{"thinking": {"type": "enabled/disabled"}}` | — | — |
| 思考强度 | `{"reasoning_effort": "low/high/max"}` | `{"output_config": {"effort": "low/high/max"}}` | `{"reasoning": {"effort": "none/low/high/max"}}` |

- 思考模式**默认开启**，服务端默认 effort 为 `high`；本项目为省费用，**默认显式传 `low`**。
- 强度映射（请求传值 → 实际生效）：`low→low`、`medium/high/xhigh→high`、`max→max`。
- 思考模式**不支持** `temperature`、`top_p`、`presence_penalty`、`frequency_penalty`（传了不报错、不生效）。
- OpenAI SDK 中 `thinking` 需放入 `extra_body`；**本项目用 OkHttp 直传 JSON，无此坑**。

**A.3 思维链（reasoning_content）回传规则**

| 场景 | 是否回传历史思维链 | 本项目处理 |
|---|---|---|
| 请求不带 `tools` | 无需回传（传入也被忽略） | 装配 payload 时省略 |
| 请求带 `tools`（联网搜索） | **必须回传全部历史轮次** | 从 DB 读回并拼接（§4.5） |

思维链与 `content` 同级返回；DB 保留 `reasoning_content` 字段即为该场景预留。

**A.4 联网搜索（原生 web_search）**

- 端点 `POST /responses`；`tools: [{"type": "web_search"}]`；服务端执行，模型自主决定是否搜索。
- 目前仅 `deepseek-v4-flash` 支持；`tool_choice` 可设 `{"type": "web_search"}` 强制搜索。
- 开关打开时请求切至 `/responses`；关闭时用回 `/chat/completions`。

**A.5 文件上传（Files API）**

- `POST /files`，`multipart/form-data`：`file`（必填）+ `purpose=user_data`（必填）；可选 `expires_after[anchor]=created_at`、`expires_after[seconds]`（3600–2592000，不传则永久）。
- 限制：单文件 ≤ 64MiB；上传需 10 分钟内完成；支持 JPEG / PNG / GIF / WebP（按内容判断）。
- 对话中使用：`messages` 里以 `file` 内容块引用 `file_id`，配合 `deepseek-v4-flash-vision-exp` 模型。
- **仅支持图片**；文档类内容需自行转文本发送。

**A.6 余额查询**

```json
{
  "is_available": true,
  "balance_infos": [
    { "currency": "CNY", "total_balance": "110.00",
      "granted_balance": "10.00", "topped_up_balance": "100.00" }
  ]
}
```

启动时与手动刷新时调用；`is_available:false` 明确提示"余额不足，请充值"。

**A.7 模型列表**

- `GET /models` 返回 `data[]`，对 ID 做模糊匹配；启动时刷新并缓存。
- 已知模型：`deepseek-v4-flash`、`deepseek-v4-pro`、`deepseek-v4-flash-vision-exp`。

**A.8 错误码**

| 码 | 含义 | 处理 |
|---|---|---|
| 400 | 格式错误 | 按错误信息修请求体 |
| 401 | 认证失败 | 提示检查 Key |
| 402 | 余额不足 | 提示充值 |
| 422 | 参数错误 | 按错误信息修参数 |
| 429 | 限流 | 指数退避重试（1s→2s→4s→8s，±50% 抖动） |
| 500 | 服务器故障 | 等待后重试，最多 2 次 |
| 503 | 服务器繁忙 | 稍后重试 |

网络超时：120 秒。

**A.9 Chat Completions 参数汇总**

| 参数 | 类型 | 说明 |
|---|---|---|
| `model` | string | 模型 ID |
| `messages` | object[] | 完整历史（无状态 API 必须全量携带） |
| `thinking` | object | `{"type": "enabled/disabled"}` |
| `reasoning_effort` | string | `low / high / max`（默认 high，本项目默认 low） |
| `max_tokens` | integer | 生成上限（本项目不主动设置） |
| `stream` | boolean | 本项目默认 `false` |
| `tools` | object[] | 联网搜索时使用 |
| `tool_choice` | object | 控制工具调用策略 |
