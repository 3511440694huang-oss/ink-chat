# 在 Android 设备上构建 APK —— 实战心得

> 来源：AI 小说工坊（novel-agent）首发；经 ink-chat / edge-guard 全周期实测修订
> 环境：arm64 手机 / Termux + Ubuntu proot / 工作区在 /storage/emulated/0（fuse 挂载）
> 工具链：Gradle 8.11.1 + AGP 8.8.2 + Kotlin 2.0.21 + JDK 17，SDK 36 + build-tools 35.0.0

---

## 一、环境层：80% 的坑在这里（已一次性固化）

### 1. aapt2 架构坑（第一次构建必踩）

**现象**：`:app:processDebugResources` 失败，日志报 `AAPT2 ... error=2`（No such file or directory）。

**真相**：错误码被包装过，实际是 `Exec format error` —— AGP 从 Google Maven 下载解压的
aapt2 是 **x86_64 ELF**，在 arm64 手机上根本无法执行。

**解决（双保险，已固化）**：
1. 使用本机静态编译的 arm64 版（固定在 `/root/aapt2-bin/aapt2`）；
2. `local.properties` 指向外部二进制：
   ```properties
   android.aapt2FromMavenOverride=/root/aapt2-bin/aapt2
   ```
3. 兜底：AGP 从缓存 / transforms 中重新解压出 x86_64 版时，把 arm64 二进制覆写回缓存 jar：
   ```bash
   # 缓存位置（AGP 8.8.2 对应 8.8.2-12006047）
   JAR=~/.gradle/caches/modules-2/files-2.1/com.android.tools.build/aapt2/8.8.2-12006047/*/aapt2-8.8.2-12006047-linux.jar
   cd /tmp && mkdir -p _aapt2 && cd _aapt2
   unzip -o $JAR aapt2
   cp /root/aapt2-bin/aapt2 ./aapt2 && chmod +x aapt2
   zip -f $JAR aapt2        # 替换 jar 内二进制
   rm -rf ~/.gradle/caches/8.11.1/transforms/*   # 清 transforms 缓存重建
   ```

**教训**：先修工具链再碰代码，否则每次构建都死在同一处。

### 2. noexec / fuse 工作区与构建脚本

- 需要“执行”的东西（JDK、aapt2 覆盖件）一律来自 Ubuntu 侧；源码与产物留在工作区即可；
- **实测**：无需把源码拷进 Ubuntu 内——直接在工作区原地构建即可。每个项目自带同构
  `build.sh`（已封装环境变量与日志）：
  ```bash
  bash build.sh                            # 默认构建 debug APK
  bash build.sh :app:compileDebugKotlin    # 只过 Kotlin 编译（最快暴露代码错误）
  bash build.sh :app:assembleRelease       # 构建 release APK
  bash build.sh :app:testDebugUnitTest     # 跑单元测试
  ```
  脚本内置：`JAVA_HOME`（java-17-openjdk-arm64）、`ANDROID_HOME`（`/storage/.../02-工具链/android-sdk`）、
  Gradle 8.11.1（`/storage/.../02-工具链/toolchain`），日志 `tee /tmp/<项目>-build.log`、退出码透传；
- 构建日志一律落盘再读，避免长时间输出把会话刷爆；
- 同源的 fuse 副作用：**git 写对象可能失败**（`git add` 报 "failed to insert into database"）
  → 仓库改用 `--separate-git-dir`，把对象库放到 `/root`（如 `/root/ink-chat.gitdir`）。

### 3. targetSdk 策略

- Android 15+（API 35+）对从 app 数据目录执行 ELF 有额外限制；
- 锁定已验证组合：**compileSdk 36 / targetSdk 34**；minSdk 按项目取 23–26。

### 4. SELinux 与安装、启动验证

- `system_server` 直接 `pm install` 读 `/storage/emulated/0`（fuse）下的 APK 会被 SELinux 拒绝；
- 正确姿势（root shell）：
  ```bash
  cp xxx.apk /data/local/tmp/ && pm install -r /data/local/tmp/xxx.apk
  ```
- 验证三连 + 一致性校验：
  ```bash
  am start -n com.xxx/.MainActivity
  pidof com.xxx                                       # 进程存活
  logcat -d -t 300 | grep -E "FATAL|AndroidRuntime"   # 无输出 = 无崩溃
  sha256sum /data/local/tmp/xxx.apk app/build/outputs/apk/release/app-release.apk   # 两值一致
  ```

## 二、构建配置层

### 1. 签名

- 复用 keystore 时 **复制进本项目**（`keystore/` 目录），不要跨项目相对路径引用——目录一挪就废；
- debug / release 挂钩同一个 signingConfig，命令行打包省心。

### 2. 逐轮修错的节奏

第一轮错误几十个很正常，按这个顺序收敛：**先 Kotlin → 再资源（aapt2）→ 最后 Dex / 打包**。
一次只修一类错误，改完立即重跑。日志用 grep 快速提取：

```bash
./gradlew assembleDebug 2>&1 | tee /tmp/build.log
grep -nE "^e: |error:" /tmp/build.log | head -50
```

- kapt 报诡异错误或增量结果异常时，清缓存重跑（ink-chat 实测有效）：
  ```bash
  rm -rf app/build/generated/source/kapt app/build/tmp/kapt3
  ```
- KDoc 里禁写 `\underset` 这类 `\u` 开头的序列——javac / kapt 会把注释当非法
  Unicode 转义，stub 编译失败。

### 3. 验证过的版本组合（锁定，不要升级）

- Gradle 8.11.1 + AGP 8.8.2 + Kotlin 2.0.21 + JDK 17；
- 常用库：Compose BOM 2024.02.00 / Room 2.6.1 / OkHttp 4.12.0 / Koin 3.5.6 / DataStore；
- 注解处理：**用 kapt**（KSP 适配折腾后弃用）。

## 三、代码层：高频坑位清单（编号被下游文档引用，勿重排）

### Room

1. **列名必须显式对齐**：Kotlin 属性是 camelCase，SQL 写 snake_case → 每个字段加
   `@ColumnInfo(name = "...")`，否则运行时 `no such column`；
2. `@Query` 投影不支持 `Triple` 等非 POJO 类型 → 定义 data class；
3. 开发期 schema 变更：`fallbackToDestructiveMigration()` 省事。

### Kotlin

4. `@Synchronized` 不能标注 `suspend` 函数 → 用 `synchronized(lock) {}` 或 Mutex；
5. `'\n' == 10` 编译不过，用 `'\n'.code`；
6. 跨模块返回多值慎用 Triple，POJO 更稳。

### Compose

7. `LazyColumn` 里必须 `item { ... }` 包裹 composable；
8. `LaunchedEffect(key)` + `delay()` 做“停止输入 2 秒自动保存”时，注意 key 变化会
   取消协程重开的语义。

### Koin

9. 参数化注入：module 里 `factory { (id: String) -> ... }`，使用时 `get<T> { parametersOf(id) }`；
10. UI 层拿应用级容器：companion 持 lazy 的全局 context。

### 网络 / 流式

11. SSE 解析：按行、`data: ` 前缀、`[DONE]` 收尾；delta 里区分 `content` 与 `reasoning_content`；
12. 加一层 JSON 清洗（去 markdown 围栏、尾逗号容错）显著降低解析失败率；
13. 限速重试：指数退避 + 对 429 / 5xx 专门处理。

## 五、一句话总结

> 设备上构建 APK：**80% 时间花在环境**（aapt2 架构、fuse / noexec、缓存），20% 花在代码。
> 环境问题一次性固化（local.properties / build.sh），之后就是正常的改错循环。
> 代码层最阴的是 **Room 列名**与 **Koin 参数注入**；工作区最大的隐形雷是 **fuse 上的 git 对象库**。
