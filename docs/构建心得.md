# 在 Android 设备上构建 APK —— novel-agent 实战心得

> 来源：AI 小说工坊（novel-agent）从零到装机验证的完整过程
> 环境：arm64 手机 / Termux + Ubuntu proot / 工作区在 /storage/emulated/0（fuse 挂载）
> 工具链：Gradle 8.11.1 + AGP 8.8.2 + Kotlin 2.0.21 + JDK 17，SDK 36 + build-tools 35.0.0

---

## 一、环境层：80% 的坑在这里

### 1. aapt2 架构坑（第一次构建必踩）

**现象**：`:app:processDebugResources` 失败，日志报 `AAPT2 ... error=2`（No such file or directory）。

**真相**：错误码被包装过，实际是 `Exec format error` —— AGP 从 Google Maven 下载解压的
aapt2 是 **x86_64 ELF**，在 arm64 手机上根本无法执行。

**解决（本次采用的双保险）**：
1. 准备一份 arm64 静态编译的 aapt2（本机固化在 `/root/aapt2-bin/aapt2`）；
2. `local.properties` 加一行，让 AGP 直接用外部二进制：
   ```properties
   android.aapt2FromMavenOverride=/root/aapt2-bin/aapt2
   ```
3. 兜底：把该二进制覆写进 Gradle 缓存里的 aapt2 jar（防止 AGP 从缓存/transforms 中
   重新解压出 x86_64 版后绕过 override）：
   ```bash
   # 缓存位置（AGP 8.8.2 对应 8.8.2-12006047）
   JAR=~/.gradle/caches/modules-2/files-2.1/com.android.tools.build/aapt2/8.8.2-12006047/*/aapt2-8.8.2-12006047-linux.jar
   cd /tmp && mkdir -p _aapt2 && cd _aapt2
   unzip -o $JAR aapt2
   cp /root/aapt2-bin/aapt2 ./aapt2 && chmod +x aapt2
   zip -f $JAR aapt2        # 替换 jar 内二进制
   rm -rf ~/.gradle/caches/8.11.1/transforms/*   # 清 transforms 缓存重建
   ```

**教训**：设备上构建，先把工具链修到能跑，再碰代码。否则每次构建都死在同一处。

### 2. noexec 与 fuse 文件系统

- `/storage/emulated/0` 是 fuse 挂载且 **noexec**：可读写、不可执行。
- 任何需要“执行”的东西（二进制、构建中间产物、Gradle 工作目录）都放在 Ubuntu 环境内
  的路径执行；工作区目录只当“源码 + 产物”的中转站。
- 构建日志重定向到文件再读，避免长时间输出把会话刷爆。

### 3. targetSdk 策略

- Android 15+（API 35+）对从 app 数据目录执行 ELF 有额外限制；
- 本设备自构建场景沿用工作区已验证策略：**compileSdk 36 / targetSdk 34 / minSdk 26**，
  与 dsh-mobile-apk、html2apk 保持一致。

### 4. SELinux 与安装、启动验证

- `system_server` 直接 `pm install` 读 `/storage/emulated/0`（fuse）下的 APK 会被 SELinux 拒绝；
- 正确姿势（root shell）：
  ```bash
  cp xxx.apk /data/local/tmp/ && pm install -r /data/local/tmp/xxx.apk
  ```
- 启动验证三连：
  ```bash
  am start -n com.novel.agent/.MainActivity
  pidof com.novel.agent                       # 进程存活
  logcat -d -t 300 | grep -E "FATAL|AndroidRuntime"   # 无输出 = 无崩溃
  ```

## 二、构建配置层

### 1. 签名

- 复用 keystore 时 **复制进本项目**（`keystore/` 目录），不要跨项目相对路径引用——目录一挪就废；
- debug / release 挂钩同一个 signingConfig，命令行打包省心。

### 2. 逐轮修错的节奏

第一轮错误几十个很正常，按这个顺序收敛：

1. 先让 Kotlin 编译过（`:app:compileDebugKotlin`）；
2. 再让资源链接过（aapt2）；
3. 最后 Dex / 打包。

一次只修一类错误，改完立即重跑。日志用 grep 快速提取：

```bash
./gradlew assembleDebug 2>&1 | tee /tmp/build.log
grep -nE "^e: |error:" /tmp/build.log | head -50
```

### 3. 本次验证可用的版本组合

- Gradle 8.11.1 + AGP 8.8.2 + Kotlin 2.0.21 + JDK 17
- Compose BOM 2024.02.00 / Room 2.6.1 / OkHttp 4.12.0 / Koin 3.5.6 / DataStore 1.0.1
- 注解处理：KSP 版本适配折腾后，**改用 kapt** 稳定跑通（Room 两种都支持）

## 三、代码层：高频坑位清单

### Room

1. **列名必须显式对齐**：Kotlin 属性是 camelCase，DAO 的 SQL 写 snake_case
   → 每个字段加 `@ColumnInfo(name = "...")`，否则运行时 `no such column`；
2. `@Query` 投影不支持 `Triple` 等非 POJO 类型 → 定义 data class；
3. 开发期 schema 变更：`fallbackToDestructiveMigration()` 省事。

### Kotlin

4. `@Synchronized` 不能标注 `suspend` 函数 → 用 `synchronized(lock) {}` 或 Mutex；
5. `'\n' == 10` 编译不过，用 `'\n'.code`；
6. 跨模块返回多值慎用 Triple，POJO 更稳。

### Compose

7. `LazyColumn` 里必须 `item { ... }` 包裹 composable；
8. `LaunchedEffect(key)` + `delay()` 实现“停止输入 2 秒自动保存”时，注意 key 变化会
   取消协程的语义。

### Koin

9. 参数化注入：module 里 `factory { (id: String) -> ... }`，使用时 `get<T> { parametersOf(id) }`；
10. UI 层拿应用级容器：companion 持 lazy 的全局 context。

### 网络 / 流式

11. SSE 解析：按行、`data: ` 前缀、`[DONE]` 收尾；delta 里区分 `content` 与 `reasoning_content`；
12. 加一层 JSON 清洗（去 markdown 围栏、尾逗号容错）显著降低解析失败率；
13. 限速重试：指数退避 + 对 429 / 5xx 专门处理。

## 四、Agent 应用设计心得（本项目主菜）

1. **工具越确定越好**：read / write / edit / check / stats / update_state 六个原子工具，
   优于一个万能 RUN 工具。可审计、可回放、防幻觉；
2. **状态机用 System 消息注入**：在 messages 里插 `role=system` 的强制指令，而不是伪装
   tool 消息——不破坏 OpenAI 协议，各家 API 都兼容；
3. **上下文对 prefix cache 友好**：前缀（system prompt + 核心摘要）永不裁剪；裁剪只发生在
   尾部窗口；历史用摘要表归档；
4. **快照限幅**：环形保留 N 版 + 项目总量上限（50MB）+ 单文件上限（1MB 降级），防存储爆炸；
5. **无进展检测**：滑动窗口检测“反复写非目标文件”→ 中止，防死循环烧 token；
6. **强制摘要更新**：写设定文件的工具必须带 `summary_update` 参数，否则拒绝执行——保证
   “创作圣经”永不过期。

## 六、一句话总结

> 设备上构建 APK：**80% 时间花在环境**（aapt2 架构、noexec、缓存），20% 花在代码。
> 环境问题一次性固化（local.properties / 脚本 / README），之后就是正常的改错循环。
> 代码层最阴的是 **Room 列名** 和 **Koin 参数注入**——报错信息明确，但第一次见容易懵。
